✅ 앱 실행 확인
1
기본 Flask 앱 구조 생성
필수
Python Flask로 가장 단순한 웹앱을 만들어줘. 요구사항: - app.py 파일 하나로 시작 - "/" 경로에 "Hello, World!" 를 보여주는 홈페이지 - templates/index.html 파일 (Bootstrap 5 CDN 사용, 깔끔한 디자인) - requirements.txt 파일 포함 (Flask, python-dotenv) - .gitignore 파일 포함 (venv, __pycache__, .env, *.pyc 제외) - .env 파일 예시 (SECRET_KEY 포함) - README.md 파일 포함 (실행 방법 포함) 폴더 구조도 먼저 보여주고 파일을 만들어줘.
2
가상환경 세팅 및 패키지 설치
필수
가상환경을 만들고 패키지를 설치해줘. 1. python -m venv venv 로 가상환경 생성 2. 가상환경 활성화 명령어 알려주기 - Windows: venv\Scripts\activate - Mac/Linux: source venv/bin/activate 3. pip install -r requirements.txt 실행 4. pip list 로 설치된 패키지 확인 각 단계 명령어를 알려주고, 오류가 생기면 바로 고쳐줘. 가상환경이 활성화되면 터미널 앞에 (venv) 가 붙어야 해.
3
Flask 앱 실행 및 브라우저 확인
필수
Flask 앱을 실행하고 브라우저에서 확인할게. 1. flask run 또는 python app.py 로 실행 2. http://localhost:5000 에서 확인 실행 안 되면 오류 메시지를 보고 바로 고쳐줘. 개발 중에 코드 수정 시 자동 재시작되도록 app.run(debug=True) 설정도 해줘.
4
페이지 추가 및 기본 레이아웃 꾸미기
선택
홈페이지를 좀 더 그럴듯하게 만들어줘. 추가 요구사항: - Bootstrap 5 네비게이션 바 (홈, 소개, 연락처 메뉴) - 히어로 섹션 (제목 + 설명 텍스트 + 버튼) - base.html 템플릿으로 공통 레이아웃 분리 - /about 경로 추가 (소개 페이지) - 반응형 디자인 (모바일에서도 잘 보이게) 내 서비스 이름은 [여기에 서비스 이름 입력] 이야.

원격 연결 & push
1
Git 초기화 및 첫 번째 커밋
필수
이 프로젝트를 Git으로 관리하도록 초기화해줘. 1. git init 2. git status 로 현재 상태 확인 3. .gitignore 파일이 제대로 있는지 확인 (venv/, __pycache__/, .env, *.pyc 가 포함되어야 함) 4. git add . 5. git commit -m "feat: 초기 Flask 앱 세팅" 커밋 전에 .env 파일이나 민감한 정보가 절대 포함되지 않는지 반드시 확인해줘. git status 결과에서 추적되는 파일 목록도 보여줘.
2
GitHub 원격 저장소 연결 및 push
필수
GitHub 원격 저장소와 연결하고 첫 push를 해줘. 내 GitHub 저장소 URL: https://github.com/[내 아이디]/[저장소 이름].git ↑ 위 URL을 실제 내 저장소 URL로 바꿔서 실행해줘. 실행 순서: 1. git remote add origin [URL] 2. git branch -M main 3. git push -u origin main push 후 GitHub 웹사이트에서 파일이 올라갔는지 확인하는 방법도 알려줘. 인증 오류 나면 GitHub Personal Access Token 발급 방법도 안내해줘.
3
Git 기본 설정 (이름, 이메일)
처음 1회만
Git 사용자 정보가 설정되어 있는지 확인하고, 없으면 설정해줘. 확인 명령어: git config --global user.name git config --global user.email 설정 명령어: git config --global user.name "[내 이름]" git config --global user.email "[GitHub 가입 이메일]" GitHub 계정과 이메일을 일치시켜야 커밋 기여도가 프로필에 표시돼.

🤖 자동 검사
1
변경사항 커밋 & push (매번 사용)
반복 사용
방금 수정한 내용을 GitHub에 올려줘. 1. git status 로 변경된 파일 목록 확인 2. git diff 로 무엇이 바뀌었는지 요약해줘 3. git add . 4. 변경 내용에 맞는 커밋 메시지 제안해줘 (한국어로, feat/fix/refactor/docs 중 택1 붙여서) 5. git commit -m "[커밋 메시지]" 6. git push origin main push 완료 후 GitHub Actions 탭에서 자동 검사가 통과했는지 확인하는 방법도 알려줘.
2
GitHub Actions CI 자동화 설정
권장
GitHub에 push할 때마다 자동으로 테스트가 돌아가도록 GitHub Actions를 설정해줘. .github/workflows/ci.yml 파일 생성: - main 브랜치에 push되면 자동 실행 - Python 3.11 환경 세팅 - pip install -r requirements.txt - Flask 앱이 문법 오류 없이 import 되는지 확인 - (선택) flake8 코드 스타일 검사 설정 완료 후 push해서 GitHub 저장소의 Actions 탭에서 초록색 체크가 뜨는지 확인해줘. 실패하면 오류 메시지 보고 바로 고쳐줘.
3
브랜치 전략 설정 (기능별 개발)
선택
새 기능을 추가할 때 브랜치를 분리해서 안전하게 개발하는 방법을 알려줘. 브랜치 전략: - main: 항상 배포 가능한 안정 버전 - feature/기능명: 새 기능 개발용 - fix/버그명: 버그 수정용 지금 추가하려는 기능: [기능 이름 입력] 1. git checkout -b feature/[기능명] 2. 기능 개발 후 커밋 3. git checkout main 4. git merge feature/[기능명] 5. git push origin main 이 흐름으로 진행해줘.
STEP 04
무료 서비스로 배포 + 데이터베이스 연결
실제 인터넷에서 누구나 접속할 수 있게 배포합니다. Render.com (권장) 또는 Railway.app을 사용합니다.
🟢 Render.com (권장)
  • 무료 플랜 영구 제공
  • PostgreSQL 무료 90일
  • GitHub 자동 배포 연동
  • 15분 비활성 시 슬립 (단점)
  • 커스텀 도메인 지원
🔵 Railway.app
  • 월 $5 크레딧 무료 제공
  • PostgreSQL 포함
  • 슬립 없이 항상 실행
  • 크레딧 소진 시 중단 (단점)
  • 설정이 더 간단함
💡 Render.com 또는 Railway.app에 가입하고 GitHub 계정과 연결해두세요. 아래 지시문 중 원하는 서비스를 선택해서 사용하면 됩니다.
1
Render 배포 준비 (앱 설정)
필수
Render.com에 배포할 수 있게 앱을 준비해줘. 1. gunicorn 을 requirements.txt에 추가 2. Procfile 파일 생성: web: gunicorn app:app 3. render.yaml 파일 생성 (Web Service 자동 설정) 4. 환경변수 목록 정리 (.env.example 파일 생성) - SECRET_KEY - DATABASE_URL - FLASK_ENV=production 5. app.py에서 debug=True 가 production에선 자동으로 꺼지도록 설정 변경사항 GitHub에 커밋&push까지 해줘.
2
PostgreSQL 데이터베이스 연결
필수
Flask 앱에 PostgreSQL 데이터베이스를 연결해줘. 사용할 패키지: - Flask-SQLAlchemy (ORM) - psycopg2-binary (PostgreSQL 드라이버) - Flask-Migrate (DB 스키마 관리) 해줘야 할 것: 1. requirements.txt 업데이트 2. app.py에 SQLAlchemy 설정 추가 3. models.py 파일 생성 (예시 모델 1개 포함) 4. DATABASE_URL 환경변수로 관리 5. flask db init / migrate / upgrade 명령어 설명 로컬에서는 SQLite로 테스트하고 배포 환경에서는 PostgreSQL 사용하도록 자동 전환되게 설정해줘.
3
Render에서 실제 배포하기
필수
Render.com에서 실제로 배포하는 방법을 단계별로 알려줘. 1. render.com 로그인 후 New Web Service 클릭 2. GitHub 저장소 연결 방법 3. 환경변수 입력 위치와 방법 (SECRET_KEY, DATABASE_URL 등) 4. Free PostgreSQL 데이터베이스 생성 방법 5. 배포 로그 확인 방법 6. 배포 완료 후 접속 URL 형태 설명 (예: https://my-app.onrender.com) 배포 중 오류가 나면 어떤 로그를 봐야 하는지도 알려줘.
4
Railway.app 대안 배포
선택
Render 대신 Railway.app으로 배포할게. Railway 방식으로 설정해줘. 1. railway.toml 설정 파일 생성 2. nixpacks.toml 또는 Procfile 설정 3. Railway CLI 설치 및 로그인 방법 4. railway up 으로 배포하는 방법 5. Railway 대시보드에서 PostgreSQL 플러그인 추가하는 방법 6. 환경변수 설정 방법 월 무료 크레딧 한도와 모니터링 방법도 알려줘.

1
새 기능 추가 요청 (범용 템플릿)
반복 사용
현재 Flask 앱에 새 기능을 추가해줘. 추가할 기능: [원하는 기능을 한 문장으로 설명] 예시: - 사용자 회원가입 / 로그인 기능 - 게시글 작성, 수정, 삭제 (CRUD) - 검색 기능 추가 - 파일 업로드 기능 - 카카오 또는 구글 소셜 로그인 - REST API 엔드포인트 추가 요구사항: - 기존 코드 스타일과 구조 유지 - 새 패키지 필요 시 requirements.txt 업데이트 - 기능 동작 테스트 방법 알려주기 - 완료 후 GitHub 커밋 & push
2
오류 발생 시 디버깅 요청
반복 사용
앱 실행 중 오류가 발생했어. 고쳐줘. [아래에 오류 메시지 전체를 붙여넣기] --- 오류 메시지: --- 발생 상황: [어떤 동작을 했을 때 오류가 났는지] 1. 오류 원인 분석해줘 2. 코드 수정해줘 3. 수정 후 같은 오류 재현되는지 확인 방법 4. 같은 패턴의 오류가 다른 곳에도 있는지 점검 5. 수정 완료되면 GitHub 커밋&push
3
배포 오류 디버깅 (Render/Railway)
반복 사용
로컬에서는 잘 되는데 배포 환경에서 오류가 나. [아래에 Render/Railway 배포 로그를 붙여넣기] --- 배포 로그: --- 배포 서비스: Render / Railway (해당하는 것 선택) 1. 배포 실패 원인 분석 2. 로컬과 배포 환경 차이점 설명 3. 환경변수, 포트, 패키지 버전 문제인지 확인 4. 코드 또는 설정 파일 수정 5. 수정 후 재배포 방법 안내
4
코드 리뷰 및 보안 점검
월 1회 권장
현재 코드 전체를 리뷰하고 개선점을 알려줘. 체크해줄 것: - 보안 취약점 (SQL Injection, XSS, CSRF) - 하드코딩된 비밀번호나 API 키 - 불필요한 패키지 또는 중복 코드 - 에러 핸들링이 빠진 API 엔드포인트 - N+1 쿼리 문제 (DB 성능) - 로그인 없이 접근 가능한 페이지 개선 우선순위를 높음 / 중간 / 낮음으로 나눠서 목록으로 보여주고, 높음부터 하나씩 같이 고쳐나가자.
5
UI/UX 개선 요청
선택
웹사이트 디자인과 사용성을 개선해줘. 개선하고 싶은 부분: [원하는 부분 입력] 예시 요청: - 모바일에서도 잘 보이도록 반응형 수정 - 로딩 속도 개선 (이미지 최적화, 압축) - 버튼, 폼 등 UI 요소 통일성 있게 정리 - 다크모드 추가 - 폰트 및 색상 시스템 정리 Bootstrap 5 기반으로 개선하고, 변경 전/후 화면을 설명해줘.
6
프로덕션 배포 전 최종 체크리스트
배포 직전
실제 사용자에게 공개하기 전에 프로덕션 배포 준비를 도와줘. 점검 목록: 1. DEBUG=False 설정 확인 2. SECRET_KEY가 환경변수로 분리되었는지 3. 에러 페이지 커스텀 (404, 500) 4. HTTPS 강제 리다이렉트 설정 5. DB 마이그레이션 최신 상태 확인 6. requirements.txt 버전 고정 7. 불필요한 print() 디버그 코드 제거 8. 로그 설정 (werkzeug → logging) 9. 정적 파일 캐싱 설정 빠진 부분 있으면 바로 고쳐주고 배포 후 모니터링하는 방법도 알려줘.
